# 当前架构（2026/10/10）

本项目当前是本机界面原型。

添加时的通用补全：`metadata-search.js` 在手动添加和豆瓣关联资料表单里提供候选选择，`metadata-lookup.cjs` 通过只读 `/api/metadata/search?q=` 查询 Wikidata 的片名、原名、年份、导演、类型标签、语言与地区。只填空白字段，年份冲突需先核对；不创建豆瓣关联，不引入第三方评分。服务端短时内存缓存查询结果，无用户数据库；选定资料随新增作品保存在浏览器。只有查询片名发送给 Wikimedia，不发送个人评分或观后感。

- `index.html`：网页入口。
- `style.css`：样式及响应式布局。
- `app.js`：原生 JavaScript 渲染、搜索/筛选、各视图、电影记录和豆瓣关联资料。
- `add-film.js`：豆瓣优先 / 手动添加流程、校验、保存新增作品。
- `add-search.js`：站内搜索候选、选择版本、自动关联与取消过期请求。
- `film-metadata.js`：新旧影片共用资料字段白名单；`sync-film-metadata.js` 按豆瓣 ID 从只读 `/api/douban/catalog` 补全空字段。目录是已核对资料快照，不是实时同步；用户编辑覆盖值优先，评分/观看日期等个人记录不会被资料覆盖。
- `edit-film.js`：表格单元格编辑与字段校验；`gongying.filmEdits.v1` 保存作品属性覆盖值，启动时应用于活动记录与回收站作品。双方评分可分别录入，豆瓣来源评分只读。目前仍无身份鉴权，不属于正式的双人权限控制。
- `delete-film.js`：软删除、确认、撤销与回收站恢复；`gongying.deletedFilms.v1` 保存被删除作品 ID，原始作品资料不会永久删除。启动时从活动列表排除这些 ID，刷新后可从回收站恢复。
- `douban-lookup.cjs`：豆瓣条目资料读取与已核对快照，访问受限时返回提示，不绕过验证。
- `server.cjs`：Node.js 内置 HTTP 服务，监听 127.0.0.1:4173；静态文件加只读 `/api/douban?id=条目ID` 与 `/api/douban/search?q=片名`。没有写入 API、鉴权或数据库。
- 浏览器 localStorage：保存 `gongying.hiddenColumns`（隐藏列偏好）和 `gongying.addedFilms.v1`（新增影片与豆瓣关联）。最初十条电影记录仍在 app.js 中。

访问不同浏览器或设备不会自动同步数据。新增作品已可保存，“写感受”仍是原型入口。清除浏览器网站数据将丢失新增作品；尚未实现云端备份。

## 豆瓣关联

`doubanSources` 保存已核对条目的 ID、可核对评分快照、来源 URL。评分是公开页面或索引中的快照，不代表实时查询结果，不会自动刷新。不能获取评分时展示“查看豆瓣”，未核实具体条目时展示“待关联”并打开豆瓣电影搜索。详情页标注来源和录入日期。

添加流程在站内请求本机搜索接口，接口访问豆瓣候选建议服务（非承诺稳定的官方 API）。输入片名后展示最多 8 个候选，带年份、原名与可获取的导演；点击后自动关联并带入资料。搜索结果最多缓存 3 分钟、50 组，仅在服务器内存中。豆瓣搜索不可用时仅展示明确提示的已保存匹配，不将访问失败当作不存在。

已核对条目使用明确标注的快照，其余尝试读取公开页面，8 秒超时。网页读取遇到 403/429 或安全验证时不绕过验证，自动保留候选片名、年份、原名和豆瓣链接供手动补全，没有实现实时 API 同步。独立个人评分不受豆瓣评分影响。

## 双人正式使用的后续架构

浏览器前端 → 业务 API → 共享数据库；通过两人独立身份区分评分和观后感。

影视资料与个人记录分开存储，影视资料持有豆瓣条目 ID、评分来源及更新时间。未揭晓的感受必须由服务端控制可见性。具体数据库与部署方式尚未选定，本次没有迁移或部署。
