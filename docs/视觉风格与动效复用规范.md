# 暖暗像素宇宙：视觉风格与动效复用规范

版本：2026-10-20 / V1.0。基准：当前像素日程完整功能版。

2026-10-27 扩展：本规范的视觉基准已应用到像素入口的电影、图书、游戏、惩罚、年度回顾及详情弹窗。所有页面共用 `body.pixel-theme` 下的复古屏幕变量；日程原有动效不变，其他页面保留原布局和业务流程，只统一表面材质、字体、图标、交互状态与配色。白色原版入口继续保留，不受本主题影响。

使用方式：下次可以直接将本文件全文复制给 AI，并在末尾补充本次需要修改的模块。本文件是可复用的设计与交互要求，不是要求一次性重做网站的任务清单。

## 1. 执行原则与适用范围

请沿用已经确认的视觉风格和交互方式，在我指定的范围内修改，不重新探索艺术方向。保留已有数据、业务能力和已经认可的动效。

- 正式参考入口为 `/pixel-schedule.html#schedule`，不是白色原版 `/`，也不是早期只读样机 `/orbit-preview.html`。
- 原版和像素完整功能版共用真实数据库，不得为了展示效果擅自添加、删除或修改真实记录。写入测试使用内存数据。
- 当前基准是暖暗宇宙背景、前侧浅弧时间轴和下半区复古屏幕面板；不是完整椭圆轨道、中心星球或可上下旋转的三维场景。
- 用户已实际认可「长按记录化成像素格，再收合为可拖动小块」效果，后续同类需求优先复用这套实现。
- 不把旧版仍保留的代码自动视为当前启用的效果；须检查像素入口的实际分支与最终覆盖样式。

## 2. 总体美术方向

风格关键词：暖暗色、复古显示屏、静态细扫描纹理、清晰像素图形、像素小角色、柔和琥珀荧光、太空与宇宙、轻微玻璃内凹感。

整体应像在暖暗太空中操作一块复古飞船屏幕，但不要做成军事终端、密集仪表盘或代码控制台。保持温暖、安静、有空间层次，交互反馈明确。

### 2.1 配色

沿用现有变量，避免给不同模块各自发明一套颜色。

| 用途 | 当前基准 |
| --- | --- |
| 宇宙底色 | `#191714`，暖黑棕 |
| 面板屏幕 | `#201b17` |
| 面板外壳 | `#39312bec` |
| 抬高层 | `#352b23` |
| 主要文字 | `#f2dfbf` |
| 次要文字 | `#c2ac90` |
| 柔和琥珀重点 | `#efb67c` |
| 较高饱和橙色 | `#f2a45f`，用于今天、主要交互和视觉焦点 |
| 边缘与分隔 | `#b4946d38` / `#d5b38620`，低对比 |

内容类别可沿用电影暖杏、图书灰绿、游戏淡金、日常灰紫、惩罚暖陶色。不要让所有元素同时发光或同时使用高饱和橙色。

### 2.2 材质、轮廓与层级

- 扫描纹理是静态细横线：约每 3px 一组，其中约 1px 为低透明度暖色线。不是粗条纹、随机故障、自动闪烁或大颗粒马赛克。
- 屏幕采用轻微内凹阴影、低亮反光和暗角；参考现有 `--retro-glass`、`--retro-well`、`--cabin-*`。
- 背景有疏密与明暗不同的像素星点、少量十字星、星座和月牙，不能压过时间轴和正文。当前背景装饰是静态的，不要求增加持续漂移或镜头视差。
- 下半区是同一套复古屏幕内的操作层，不是纯白卡片，也不是每一层都套厚重边框。
- 面板外壳保留圆弧屏角；按钮和内层面板采用较小圆角。不要为了像素感把所有东西改成机械直角框。
- 时间轴内容图标只保留像素主体，不额外套方形或圆形外框。数字计数标记、表单边界和可访问焦点不属于应删除的图标外框。

### 2.3 字体与图标

- 标题、日期、短标签与操作文字采用 `Consolas`，中文回退到 `Microsoft YaHei UI` / `Microsoft YaHei`。
- 评论、感受及长段文字优先中文易读字体，行高约 1.75，不强行做成难辨认的点阵字。
- 字体可以有轻微暖光和字距，但不能整体模糊、降采样、拉扁或添加 RGB 色散。
- 今日大日期可使用轻微静态扫描纹理；其他文字不得以“复古”为理由降低可读性。
- 图标采用统一的清晰像素 SVG；输入、保存、删除、日期等操作图标也必须同风格，并保留易懂含义、可访问名称和可见焦点。

## 3. 动效通用要求

- 动效必须表达状态变化或操作因果，不用装饰动画阻止输入、拖动或缩放。
- 以局部、连续、可打断的过渡为主。不要整块面板随机碎裂、满屏粒子、强闪烁或夸张弹跳。
- 优先通过 `transform` / `opacity` 实现，不逐帧改变布局尺寸，不使用 `transition: all`。
- 新操作到来时取消旧动画；快速返回、重复选择和切换步骤不能卡住、二次展开或执行过期回调。
- 尊重 `prefers-reduced-motion`。当前长按收合有用户主动开启的局部开关，不应借此放开整个网站的动画。
- 常用缓动：入场/反馈 `cubic-bezier(.23,1,.32,1)` 或 `cubic-bezier(.16,1,.3,1)`；像素格聚拢 `cubic-bezier(.65,0,.25,1)`；首次铺开 `cubic-bezier(.22,1,.36,1)`。
- 时间参数用于复用现有手感，不代表必须让每个动画都使用统一时长。

## 4. 当前启用的动效与交互清单

### 4.1 首次打开：先上半区、后下半区

这是页面过渡，不是操作引导。

- 轨道从中间向两侧缓慢铺开，约 1500ms。
- 日期和节点延迟约 700–1200ms 后显现，约 1000ms，轻微从 0.86 倍恢复。
- 月份条约延迟 800ms 开始铺开，约 1450ms；年份稍后淡入。
- 上半区基本展开后，下半区约在 2400ms 开始，1100ms 内淡入并上移约 10px。
- 计划记录约从 2600ms 起轻微错峰显现，单项约 1100ms，位移约 8px。
- 首次动画只播放一次，不因数据刷新重复播放。用户开始点击、滚轮或键盘操作时立即结束铺开，让界面完整可用。

### 4.2 时间轴：拖动、惯性与缩放

- 左右拖动平移时间，松手后保留惯性减速，不吸附到日期节点。
- 滚轮控制缩放，不把滚轮改回左右移动。缩放围绕视口中心进行。
- 缩放兼顾时间密度和节点、日期等视觉尺寸；不是只把间距拉开。当前视觉尺寸采用受限的缩放映射，不要求图标无限放大。
- 使用连续弹簧插值，缩放参数约为刚度 190、阻尼 25；日期/月居中滑动约为刚度 110、阻尼 21；自由惯性按指数衰减，衰减系数约 5。
- 点击月份长条，平滑移动到该月中旬；月份条保持连续、以色块区分月份。
- 日期按密度逐步简化：日、周、月、年。较远视图聚合事件，较近视图展开，不堆叠所有数字和名称。
- 当前默认时间密度为 36px/天；低于默认密度隐藏常驻事件名。默认及以上显示竖排名称，悬停仍可查看相应信息。
- 聚合/展开时，旧节点约 240ms 淡出，新节点约 360ms 从对应位置轻微位移、放大显现，避免突兀替换。
- 快速移动时临时弱化细小数字、文字和图形，停止后恢复；不是把文字做运动模糊。
- 保留动态扩展的时间范围，不因拖到窗口边缘突然结束探索。
- 性能约束：逻辑时间窗口与实际绘制范围分离；像素入口的日期/月/年标签只挂载视口前后约两屏，滚动时补充。不能为了无限时间范围一次生成所有屏外标签，也不能在每次缩放时重建下方计划列表。浅弧位置应缓存坐标，并按可见区间更新。

### 4.3 时间节点：靠近、悬停、聚合与固定

- 只有光标靠近节点才产生接近反馈；不能光标在整页任意位置都像选中了节点。
- 节点接近时最多轻微放大约 14%；直接悬停时约放大 18% 并上移 3px，配合柔和暖光。
- 对应日期数字可轻微下移并放大，响应约 300ms；日期数字不是另弹一个提示框。
- 同一天多个事件平时聚合为一个节点加数量，悬停后横向展开图标。展开条约 380ms，图标约 420ms，轻微错峰。
- 同一天只有一个事件，不重复弹出上方展开条。
- 下方一次只显示一条具体记录，可通过展开图标切换；不要把同日全部详情同时堆出。
- 离开后展开条约 150ms 退场；普通悬停关闭有短暂延时，允许移动到展开条或详情区。
- 点击节点固定下方详情，再点同一节点取消固定。固定状态有缓慢流动虚线描边，周期约 8 秒，使用琥珀色。
- 详情初次出现约 240ms 淡入并上移 6px；下半区详情切换另有约 220ms 的局部淡入。不要在这之外再加整个面板的展开。
- 日期快捷添加入口保留，顶部不恢复多余的「+」。

### 4.4 今天的呼吸反馈

- 今天的节点保持干净的重点色核心，外围有柔和呼吸光圈。
- 呼吸周期约 3.2 秒，外圈约在 0.8–1.5 倍之间变化，透明度约 0.3–0.65。
- 不在核心中叠加多组刻线、圆环或小符号。减少动态时保留静态标记。

### 4.5 下半区复古屏幕与逐级新建

- 「想做的事 / 还想做什么」切换时，底部短光标约 320ms 滑动，当前内容局部显现，屏幕外壳不重新展开。
- 类别以固定的像素操作入口呈现，不用旧版扇形洗牌。选定类别后收起其他类别，可通过「更换」返回。
- 每次只显示当前一小步：选择类别 → 输入/选择内容 → 日期或日期未定。已完成内容可缩成可返回的简短标签。
- 所有新建步骤默认两人一起，不显示参与人选择，不增加重复确认页。
- 当前内容退出约 80ms；新提示、图标或选项约 180ms 淡入并上移 3px，最多四个局部目标，错峰不超过 50ms。
- 页面必须像操作复古屏幕，不像打开多个终端窗口。当前可见样式已隐藏早期 SVG 接线；代码中仍有接线动画不代表应该重新显示硬连线。
- 选择项悬停以暖色和细微材质变化回应，约 160–180ms；类别按下可下移 1px，不用夸张弹性变形。
- 成功新建的记录约 480ms 从轻微上偏、0.98 倍恢复；不要让整个新建面板再执行旧版折叠动画。

### 4.6 保存反馈与文字编辑

- 电影名未编辑时像普通标题，不展示老长的输入框。输入区域随文字长度调整，年份、导演、豆瓣信息紧随标题。
- 聚焦编辑时出现流动虚线描边，约 4 秒一个循环。
- 保存成功后描边改变状态并约 1.5 秒淡出；不能失败也播放成功反馈。
- 下半区成功保存时，屏幕顶部有一条局部暖光约 600ms 扫过；减少动态时用约 180ms 的轻量透明度反馈。
- 输入焦点、保存、禁用和错误状态要清晰，但不依赖大段文字解释。

### 4.7 评分、评论卡片与海报

- 评分条的实际数值立即更新，视觉填充与滑块用弹簧追随，刚度约 400、阻尼约 32；可连续拖动，不为每次输入重建卡片。
- 滑块悬停/聚焦时约放大至 1.12 倍，约 250ms。没有评分时留空，但保留可以操作的评分入口。
- 对方评分通过卡片翻面查看，采用 Y 轴 180° 翻转、约 650ms、透视约 1000px；这不等于时间轴视角翻转。
- 海报只用于对应用户的卡片背面，悬停时约 300ms 渐显，原色呈现；正面不铺海报。
- 一人选的海报不能串到另一人的卡片；现有评分、感受及未揭晓内容的隐私规则必须保留。

### 4.8 已认可重点动效：记录收合成像素小块

完整过程必须可见且连续，不能只突然出现一个小块。

1. 按住记录约 500ms，六个 4px 充能点依次亮起；单点约 70ms。
2. 原卡片约 220ms 内从 1 倍经过 0.94 倍缩至 0.84 倍，并逐渐淡出。
3. 同位置出现覆盖整张卡片的像素网格，不是从旁边另外冒出的粒子。
4. 每格以位置与大小变化向同一小块聚拢；单格约 640ms，错峰 0–48ms，总长不超过 688ms。
5. 网格最多 72 格，完整聚拢为 24×24px 小块。类别图标约在第 540ms 开始，用 120ms 接入，形成连续交接。
6. 小块跟随鼠标；触屏时放在手指上方，避免遮挡落点。原列表占位保持不动。
7. 拖到时间轴时突出对应日期并显示日期落点。靠近视口边缘可滚动以找到目标。
8. 有效落点在保存成功后约 200ms 收入节点，并给予节点约 200ms 的亮起反馈；不能提前假装保存成功。
9. 无效落点或取消时约 240ms 返回，原记录用约 160ms 恢复。取消、失焦或页面离开时清理临时节点和动画，不修改日期。

复用时必须保留以下工程约束：

- 从按下到收合、拖动完成，原卡片和指针捕获对象必须仍是页面中的原节点。
- 不得在取得目标后重写其父列表的 `innerHTML`，也不得让关闭悬停详情的逻辑重建计划列表。
- 之前“没有充能点、没有收合、直接出现小块”的真实原因是原卡片被列表重建移出 DOM，尺寸为 0，导致像素格数量为 0。不是用户电脑性能问题，也不是这次的减少动态偏好。
- 复用 `planDragUI` / `parcelTiles` 与对应样式，不恢复仅靠裁切隐藏边缘的旧方案。
- 不克隆整张文字卡片、不把文字拉扁、不做全屏碎裂；只对当前记录形成像素收合反馈。

## 5. 不应恢复或误加的效果

- 原版新建卡片的扇形展开、洗牌、旋转和大卡片扩张，不属于当前像素版新建流程。
- 早期样机的上下拖动视角、文字站立/躺倒、完整后半圈和中心天体，不属于当前完整功能版。
- 不新增自动星空漂移、相机晃动、光标拖尾、RGB 故障或满屏随机像素；如确有新需求，先讨论。
- R4 动效诊断行是排错工具，不是正式视觉语言，也不作为其他页面的设计范例。问题确认后可单独清理，但不能借清理重做已认可的收合效果。
- 不为了“高级感”增加大面积白色面板、冷绿荧光、粗扫描线或阅读模糊。

## 6. 实现与验收

本项目对应实现：

- `frontend/pixel-schedule.css`：宇宙配色、上方文字与像素图标、轨道视觉。
- `frontend/pixel-schedule.js`：像素图标、静态星空、浅弧轨道适配。
- `frontend/pixel-console.css`：复古屏幕材质、字体、下半区与像素小块样式。
- `frontend/pixel-console.js`：局部屏幕过渡、保存反馈、像素收合与落点反馈。
- `frontend/life.js` / `frontend/life.css`：时间轴交互、首次过渡、评分惯性、标题描边、卡片翻面等共享能力。
- `frontend/composer.js`：逐步新建流程及像素入口分流。
- `frontend/timeline-engine.js`：时间密度和事件聚合。

修改后须检查：首次入场可打断；滚轮缩放/拖动惯性正常；同日聚合正确；选中可取消；分步不提前展示；快速返回不卡住；评分和保存反馈正确；长按收合全程可见；日期写入只发生一次；取消不改数据；减少动态和键盘焦点仍可用。

自动测试只能证明逻辑与回归结果，不能代替画面验收。需要分别说明“代码已检查”“测试已通过”“浏览器实际看到”“用户已认可”。无法实机检查时须明确说明，不反复宣称看不见的效果已经修好。
