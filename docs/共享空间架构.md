# 共享生活空间 · 本地实现与部署边界

## 当前已实现

六个页面：日程（默认首页）、电影、图书、游戏、惩罚、年度回顾。

日程默认是单根横向可视时间轴，混合展示全部类别，没有类别筛选、表格、文字卡片或计划列表。节点仅使用简单 SVG 线条图标，计划用虚线区分；顶部明确标注「今天」与完整年月日，刻度显示月日，并显示当前可见日期范围。默认间距 36px，可切换 56/84px 缩放。详情平时为空且隐藏，只在悬停或键盘聚焦时出现；触屏点选聚焦也可查看，编辑通过悬停框里的图标按钮打开。按住空白处拖动可平移时间轴，移动超过阈值后抑制点击，避免误新增。拖记录图标仍用于改期；点日期（不拖动）可添加。其他分类页仍是作品表格，数据和权限规则不变。

渲染技术是原生 JavaScript + HTML/CSS + 内联 SVG，不依赖 UI 框架。后续可以在现有视图层增加平移惯性、缩放过渡、悬停/节点展开动效；数据与 API 不需要因此重做。当前保留 `prefers-reduced-motion` 降低动画的设置。若未来节点数量和动效规模显著增加，再按实际性能测试决定是否换 Canvas/WebGL 渲染层，不承诺无限动画或固定帧率。

前端 `frontend/life.js` 使用业务 API，不再以浏览器 localStorage 保存正式记录。显示列偏好仍留在浏览器。服务端数据存于 `.runtime/shared-life.sqlite`，数据库、密码配置和备份目录已被 Git 忽略；新数据不会自动上传公开 GitHub。

原始十部电影和十二个观看日期，在空数据库第一次启动时初始化一次。后续不会重复初始化或覆盖修改。旧浏览器数据需要点页脚「迁移旧浏览器记录」确认后导入，旧存储不会清空；建议先在 `/backup.html` 备份。迁移是一次性事务，保留评分、日期修改与删除状态。

## 数据关系

```text
作品 works（movie / book / game）
  ├─ 日程 events（多条日期；计划 / 已做；参与人）
  └─ 评价 reviews（puppy 一份、jammy 一份）

机会 chances（获得次数、已使用次数）
  └─ 要求 demands（提出时扣一次 → 完成）
        └─ 日程 events（与要求同一事务更新）
```

电影：想看 / 在看 / 看过。图书：想看 / 在读 / 已读。游戏：想玩 / 在玩 / 已玩，另有「已结束」标记，不把玩过等同通关。日程记录做过书或游戏，会转为在读/在玩；是否读完/结束由人点选。计划过期不自动完成。同一作品的重复日程共用档案和评价。

惩罚：获得机会可累计、无过期和取消；提出要求消耗一份机会。提出者只能使用自己的机会，接受者标记完成，完成不会重复扣次数。重复提交相同操作 ID 返回原结果。要求和关联日程不能通过普通日程 API 取消或绕过完成权限。

## 账号与权限

固定账号 `puppy`、`jammy`，不开放注册。配置两个至少 12 字符的独立密码后启用真实登录，密码用 scrypt 加盐保存，登录会话只保存随机 token 的哈希。HttpOnly、SameSite Cookie，有效期 30 天；生产模式额外启用 Secure Cookie，并要求 HTTPS PUBLIC_ORIGIN。评价的归属由服务端身份决定，不能在请求里指定对方。

同时揭晓模式：双方都填写评分和感受并提交后，服务端才返回对方评分与正文。未揭晓的内容不只是前端隐藏；统计与可见数据导出也不包含它。

未配置密码时是 **仅本机开发预览模式**：页面显著提示，允许切换模拟身份；服务默认只监听 127.0.0.1。生产模式缺密码或 HTTPS 地址会拒绝启动。不可将开发预览模式直接暴露到公网。

写操作校验来源与 JSON 类型；服务有请求/登录频率限制和请求体上限。记录使用版本号避免两个页面静默覆盖；SQLite 事务保证批量删除和机会扣除不发生部分成功。限流目前在单进程内存中，云端需要分布式实现，不能当成费用硬上限。

## 运行与测试

需要 Node.js 24（使用内置 node:sqlite，目前该接口有实验性提示）。无需 npm 依赖。

```sh
node frontend/server.cjs
node --test backend/*.test.cjs frontend/*test.cjs
```

若配置账号，复制 `.env.example` 为未跟踪的 `.env`，在本机填写，再运行：

```sh
node --env-file=.env frontend/server.cjs
```

不要在聊天或 GitHub 填密码。日程拖动改期和点开修改都是同一 API；手机可用日期选择，不依赖拖动。30 秒轮询和窗口重新聚焦刷新用于同步，不是实时 WebSocket。断网不接受假保存，不实现离线编辑队列。

## 国内按量部署：尚未开通、尚未上线

当前数据库是 **本机 SQLite 验证适配器**，不是可以直接放入函数临时目录的云数据库。

分层：

- `application.cjs`：基于标准 Request/Response 的鉴权与 API 入口。
- `service.cjs`：作品、日程、评价、机会等业务规则。
- `repository.cjs`：当前 SQLite 持久化与事务实现。

迁移到阿里云 FC + Tablestore 前仍需实现并测试异步云数据库适配器（业务服务当前使用同步 repository 接口，不能直接替换成返回 Promise 的 SDK），并实现条件更新、事务、分布式幂等和限流。也需替换依赖本机 curl 的查询传输。不能上传当前 SQLite 文件到 FC 临时磁盘来声称完成持久化。

正式上线需要用户确认地区、费用/预算提醒，开通最小权限云资源，配置域名/HTTPS及适用的备案流程、两个账号的私密凭据；之后实测国内手机网络和 Wi-Fi，完成备份/恢复演练及云数据库集成测试。当前没有创建任何付费资源。

更简单的备选是 Node API + SQLite + 持久磁盘的小服务器，但不属于按调用计费方案，不能未经确认替代用户选择的按量部署。

## 备份与已有公开数据

页脚导出当前身份可见的 API 数据（不是含所有秘密和隐藏评价的管理员完整数据库备份）。运维备份需要单独备份 SQLite，并记录恢复步骤；正式云端应使用数据库备份机制。

之前经用户批准公开的 `data/` 快照保持原样；新书、游戏、日程、评分、密码不会写回该目录。不要将 `.runtime/` 或 `.env` 作为静态托管目录上传。
