# jammy和puppy的电影院 · 两人的共享记录

日程作为首页，电影、图书、游戏、惩罚和年度回顾是同一份数据的不同视图。点选记录、拖动改期，不要求每次填写评分或长感受。

开发交接与本次更新摘要：[Jammy 开发交接](docs/JAMMY_HANDOFF.md)。

## 像素日程独立版本

分支 `codex/pixel-schedule`，运行后打开 `/pixel-schedule.html#schedule`。暖暗像素宇宙、复古细扫描屏幕、分步录入与长按像素收合；共用原版 API 和真实数据库，不是测试数据副本。原版 `/` 保留，未合并到 `main`。

[视觉与动效复用规范](docs/视觉风格与动效复用规范.md) · [像素版实现与排查记录](docs/像素日程整合说明.md)。旧只读美术样机位于 `/orbit-preview.html`，不具备完整编辑能力。当前没有新增 npm 或 Three.js 运行依赖。

右上角「外观」以单行向左展开：可选原版、像素宇宙、纸白极简、奶油陶土、午夜蓝、双色印刷。五套皮肤即时切换并保留当前草稿与时间轴位置；进入或离开原版会重新载入对应页面，先保存未提交输入。窄屏可横向滑动或用滚轮浏览选项。偏好保存在当前浏览器，详见 [外观切换说明](docs/外观切换说明.md)。

## 本地运行

需要 Node.js 24，无需 npm 依赖：

```sh
node frontend/server.cjs
```

打开 http://127.0.0.1:4173/ 。未设置密码时仅为本机预览身份，可切换 puppy / jammy。数据保存在被 Git 忽略的 `.runtime/shared-life.sqlite`，不是云端数据库。

## 固定账号

复制 `.env.example` 为 `.env`，在本机设置两个至少 12 字符的独立密码，再执行：

```sh
node --env-file=.env frontend/server.cjs
```

只有 puppy 和 jammy，不开放注册；有 30 天会话、各自评价权限和服务端同时揭晓。生产模式必须配置 HTTPS PUBLIC_ORIGIN 和两个密码，否则拒绝启动。不要把预览模式暴露到公网，不要提交密码或数据库。

## 测试

```sh
node --test backend/*.test.cjs frontend/*test.cjs
```

## 数据与迁移

原始十部影片和十二个观看日期在第一次启动时初始化，之后不覆盖修改。旧浏览器新增影片、评分修改和回收站可通过页脚「迁移旧浏览器记录」确认导入，原始 localStorage 不清空；建议先用 `/backup.html` 导出旧数据。

当前服务是本机 API + SQLite，正式云服务尚未开通。阿里云 FC + Tablestore 按量部署仍需云适配器、凭据、HTTPS、费用确认及网络验证。迁移和权限细节见 [共享空间架构](docs/共享空间架构.md)。

豆瓣搜索/资料访问仍受第三方限制，评分快照不保证实时；电影可以查找 Wikidata 补全空白资料。书和游戏暂时以手动作品资料为主。上传 GitHub 不等于部署网站。

电影海报可在日程详情的「海报」入口或电影表格海报列选择。候选来自TMDB 公开搜索、豆瓣公开搜索和中英文维基百科；需核对年份、版本和来源。选择按固定账号分别保存为电影档案中的图片地址及来源，每人的海报仅在他自己的卡片背面悬停时原色显示，评价正面不放图片；电影列表分别显示 puppy / jammy 的选择，仅能修改自己的海报。旧版共用海报保留备份但不猜测归属，重新选择后写入对应账号。支持重新选择、移除，保留个人评分与日程。图片在线引用，不下载或上传图片，版权属于原权利人；第三方网络、反盗链或资源移除可能造成加载失败。

此前经用户批准公开的 [data 数据快照](data/README.md) 保持原样。新日常记录、密码和数据库不会自动上传 GitHub；导出也不会自动公开。页脚导出仅包含当前账号可见数据，未揭晓的对方感受不会导出。
